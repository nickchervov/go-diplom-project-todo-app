# Для чего создан проект 

Проект создан для закрепления и демонстрации знаний после прохождения курса GO-разработчик.

# Что делает проект 

Проект является планировщиком задач. Он хранит задачи, каждая из них содержит дату дедлайна, заголовок и комментарий. Задачи могу повторяться по заданному правилу.

Правила повторения:

* ежегодно;
* через какое-то количество дней;
* в определенные дни месяца или недели.

# Функционал API

* Добавление задачи.
* Получение списка задач.
* Удаление задач.
* Получение параметров задачи.
* Изменение параметров задачи.
* Обновление статуса задачи на выполненно.

# Структура проекта

Проект выполнен по правилам чистой архитектуры, разделен на слои domain, adapter, service, dto, controller.

1. Domain - (ядро) основные типы данных и ошибки.
2. Adapter - логика связанная с базой данных.
3. Service - основная логика.
4. dto - типы данных, являющиеся входными и выходными данными для сервиса.
5. Controller - обработчики запросов http-сервера.

В каталоге `pkg` находятся вспомогательные функции (next date, json render), файлы для миграции бд, http-сервер и файл самой базы данных sqlite.

Все методы обработчиков и сервиса выведены в отдельные go файлы.

Связь обработчиков с запросами http-сервера находится в файле `route.go`.

Переменные окружения загружаются из файла `.env` с помощью сторонней библиотеки godotenv, а чтение и значения по умолчанию централизованы в пакете `internal/config`.

# Инструкция по запуску локально

Скачайте архив и разархивируйте в любую папку.

Пример `.env` файла:

```
# Using in file config.go
TODO_PORT=7540
# Using in file config.go
TODO_DBFILE=./pkg/db/scheduler.db
# Using in file config.go
TODO_PASSWORD=PASSWORD
```

Команда для запуска сервера из корня проекта:

```
go run ./cmd/server/main.go
```

Адрес в браузере (если TODO_PORT=7540):

[http://localhost:7540](http://localhost:7540)

# Инструкция по запуску с помощью Docker

Порт по умолчанию и путь к БД заданы в образе (`TODO_PORT=7540`, `TODO_DBFILE`), а миграции уже скопированы — монтировать том не нужно.

`-e` задаёт переменные окружения внутри контейнера, `-p` публикует порт контейнера на хост. Это разные вещи: меняя порт через `-e TODO_PORT`, всё равно нужен `-p` с тем же портом, чтобы открыть сервис с хоста. Если `TODO_PASSWORD` не задан — авторизация выключена.

1. **Из корня проекта (преварительно его необходимо скачать)**

```
docker build -t todo-app:v1.0.0
docker run -e TODO_PORT=7540 -e TODO_PASSWORD=<пароль> -p 7540:7540 todo-app:v1.0.0
```

2. **Из docker hub**

```
docker pull nickchervoff/go-diplom-project-todo-app:v1.0.0
docker run -e TODO_PORT=7540 -e TODO_PASSWORD=<пароль> -p 7540:7540 nickchervoff/go-diplom-project-todo-app:v1.0.0
```
